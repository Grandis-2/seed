# 로컬 시드 데이터

로컬에서 서비스를 띄우자마자 화면 · 시연 · 부하 시험 · 정합성 검사가 되는 데이터를 명령 한 번으로 넣는다.
다시 돌리면 전부 비우고 처음부터 다시 넣는다 — 부하 시험 뒤 초기화도 이것으로 한다.

**로컬 전용이다.** Flyway 마이그레이션에 넣지 않는다. 접속 주소가 이 PC(`localhost` · `127.0.0.1` · `::1`)가 아니면 돌지 않고,
포트 포워딩으로 붙인 RDS(basedir 이 `/rdsdbbin/`)도 막는다 — 시드는 테이블을 비우고 다시 채운다.

기준: be `dev` 스키마(엔티티 id UUID v7 · 시도의 세대 · 차례 · 작업 실행 회차, 2026-10-12 마이그레이션 42개) · Mock 저장소 `epic/NV-1`(원장 회원 · 상품 `BINARY(16)`) ·
상품은 fe `develop` 의 화면 목업.

## 준비

- Python 3.12 이상 — `pip install -r requirements.txt`(Faker · PyMySQL, 버전 고정. Windows 는 tzdata 도 같이 받는다)
- be shop DB — Flyway 마이그레이션까지 적용된 로컬 MySQL 8.4
- Mock DB — Mock 저장소에서 `docker compose up -d` 로 띄운 MySQL(127.0.0.1:3307, external_mock). shop 과 같은 MySQL 에 external_mock 을 만들어도 된다

### 로컬 DB 를 처음부터 만들 때

MySQL 하나에 shop · external_mock 을 같이 만든다(운영과 같은 구성). Git Bash 에서, be · mock 저장소가 이 저장소 옆에 있다고 본다.
be 는 `dev`, mock 은 `epic/NV-1` 을 받아 둔다 — 그보다 옛 Mock 스키마는 원장 회원 · 상품 칸이 `BINARY(16)` 이 아니라 시드가 들어가지 않는다.

```bash
docker run -d --name seed-db -p 127.0.0.1:3309:3306 -e MYSQL_ROOT_PASSWORD=seed mysql:8.4 --transaction-isolation=READ-COMMITTED
# MySQL 이 뜰 때까지 20초쯤 기다린 뒤
docker exec -i -e MYSQL_PWD=seed seed-db mysql -uroot -e "CREATE DATABASE shop DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci"
for f in $(ls ../be/flyway-project/migrations/V*.sql | sort); do
  docker exec -i -e MYSQL_PWD=seed seed-db mysql -uroot --default-character-set=utf8mb4 shop < "$f"
done
docker exec -i -e MYSQL_PWD=seed seed-db mysql -uroot --default-character-set=utf8mb4 < ../mock/docs/schema.sql
```

be 에 마이그레이션이 늘면 새 파일만 같은 명령으로 적용한다.

## 실행

```bash
python seed.py --shop mysql://root:비밀번호@127.0.0.1:3306/shop
# 위 "로컬 DB 를 처음부터 만들 때" 로 만들었으면
python seed.py --shop mysql://root:seed@127.0.0.1:3309/shop --mock mysql://root:seed@127.0.0.1:3309/external_mock
```

| 옵션 | 기본값 | 뜻 |
| --- | --- | --- |
| `--shop` | 없음(필수) · 환경 변수 `SEED_SHOP_URL` | be shop DB 주소 `mysql://계정:비밀번호@호스트:포트/shop` |
| `--mock` | `mysql://nova:nova@127.0.0.1:3307/external_mock` · 환경 변수 `SEED_MOCK_URL` | Mock DB 주소(Mock compose 기본값) |
| `--reconcile-demo` | 꺼짐 | be · Mock 어긋남 15건(유령 · 누락 · 번호 · 상태 · 내용 × 3)을 더 넣는다. 정합성 검사를 보여 줄 때만. 옵션 없이 다시 돌리면 원래대로 |

20초쯤 걸린다. 끝에 검증 39항목과 요약이 나오고, 하나라도 어긋나면 종료 코드 1 로 끝난다.

## 같은 데이터 · 시각

- Faker 와 난수의 시작값을 고정했다(`steps/common.py` 의 `SEED`). Faker 버전도 `requirements.txt` 로 고정 — 버전이 바뀌면 같은 시작값에서도 다른 이름이 나온다
- 모든 시각은 실행 시각(UTC) 기준 상대값이다. 이름 · 주소 · 주문 구성 · 공개 UUID 는 매번 같고, 시각과 그 날짜가 들어간 외부 번호가 실행 시각을 따라 움직인다
- **id(UUID v7)는 실행마다 바뀐다.** be 처럼 앞자리가 생성 시각이라 id 순서가 만든 순서와 같은데, 그 시각이 실행 시각 기준이기 때문이다. 시연 계정은 `kakao_id`(`seed-00001` …)로, 예약은 공개 UUID(`preorder_token`)로 찾는다
- 그래서 시간이 지나면 상태가 저절로 바뀌는 데이터가 있다 — 일반 주문 결제 대기 15건은 몇 분 뒤 결제 기한(10분)이 지나고, 아이폰 18 Pro 결제 가능 150건은 시드 3시간 뒤부터 결제 기한(24시간)이 끝나기 시작한다. 시연 직전에 다시 돌리면 처음 상태로 돌아간다
- 대기열(waitingroom)은 회차 일정을 이벤트로 받는다. 시드 회차를 대기열에 알리려면 관리자 회차 재발행을 한 번 부른다

## 고칠 때

- 스키마가 바뀌면 그 테이블을 넣는 단계만 고친다. 테이블이 늘면 `seed.py` 의 `SHOP_TABLES` 에도 더한다(빠뜨리면 두 번째 실행이 PK 충돌로 멈추거나 이전 데이터가 남는다)
- 상품 · 카테고리는 `steps/catalog.py`, 회차 일정은 `steps/campaign.py` 의 표만 바꾼다. 예약 3,000 · 1,000건은 상품 번호 1 · 2 에 붙는다
- Faker 를 부르는 순서가 바뀌면 그 뒤 회원의 값이 다 바뀐다. 회원 컬럼을 늘리면 맨 뒤에서 부른다

## 가정 (확정되면 고친다)

- 브랜드(Apple · Samsung · LG) — fe 는 메뉴의 제조사 필터로 쓰지만 be 에 브랜드 컬럼이 없어 넣지 않는다. fe 상품 목업은 브랜드를 하위 카테고리로 두는데, 시드는 헤더 메뉴의 하위 카테고리(스마트폰 · 태블릿 …)를 쓴다
- fe 사전예약 화면은 프로모션 하나에 모델 여럿을 묶는다(아이폰 18 Pro · Pro Max). be 는 모델마다 회차 하나라 같은 일정의 회차 두 개로 넣었고, 혜택 문구는 상품 설명에 둔다
- 결제 키(`seed-pay-번호`) 형식은 가정이다. 결제 실패 후 재시도 기록은 넣지 않았다
- 드로우(럭키 드로우) 테이블은 비워 둔다

## 파일

```
seed/
├── seed.py              실행 진입점 — 접속(로컬만) · 비우기 · 단계 순서 · 검증 · 요약
├── requirements.txt     Faker · PyMySQL (버전 고정)
└── steps/
    ├── common.py        기준 시각 · id(UUID v7) · 공개 UUID · 묶어 넣기 · 이름 가리기
    ├── catalog.py       카테고리 · 상품(옵션 JSON) · 옵션 · 재고     ← 상품을 바꿀 때는 이 파일
    ├── campaign.py      회차 · 배송 차수
    ├── customers.py     회원(Faker) · 배송지 비우기
    ├── preorders.py     예약 계획 → 예약 · 이력 · 작업 · 시도 · 아웃박스 · 사전예약 주문
    ├── dead_letters.py  수신 DLQ
    ├── orders.py        주문(사전예약 + 일반) · 결제 · 재고 수량 · 장바구니 · 후기
    ├── external_mock.py Mock 원장 · 정합성 시연 세트
    └── verify.py        검증 39항목(be ⇔ Mock 원장 비교 포함)
```
